/opt/rk3588-screenbridge/bin/ffmpeg -v error -i /var/tmp/ma1/ma1-ac3.mkv -map 0:a:0 -c:a copy -f spdif - | aplay -D hw:CARD=rockchiphdmi1,DEV=0 -f S16_LE -c 2 -r 48000 -v

# Kodi was not running for this test. ffmpeg never decodes: -c:a copy takes the
# AC-3 frames as they are and -f spdif wraps them in IEC61937 bursts, which aplay
# hands to the real HDMI hw device as the 2-channel S16_LE carrier the burst is
# defined to travel in. S16_LE/2ch in hw_params is therefore the expected shape
# of a passthrough stream, not evidence against one.
#
# Carrier: S16_LE, 2 channels, 48000 Hz -> hw:CARD=rockchiphdmi1,DEV=0 (card 0, device 0)
#
# One correction was needed before the sink would decode it, and it is the whole
# reason the later ALSA config change exists:
#
#   iecset -c 0 audio off
#
# sets bit 1 of AES0 in "IEC958 Playback Default" - the IEC60958 non-audio flag -
# which is what tells the sink the stereo frames are a compressed burst. The
# card powers up at AES0=0x04 (non-audio clear, i.e. "this is PCM"). Note that
# `amixer -c 0 cset numid=15 ...` silently does not take on an IEC958-typed
# control; iecset does. The control itself is writable - the first attempt only
# looked like a driver limitation.
