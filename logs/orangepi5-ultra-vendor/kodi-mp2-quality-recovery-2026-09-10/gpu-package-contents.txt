== conffiles the package would install (NOT installed here) ==
/etc/OpenCL/vendors/mali.icd
/etc/ld.so.conf.d/00-aarch64-mali.conf
/etc/profile.d/mali-priority.sh
  /etc/ld.so.conf.d/00-aarch64-mali.conf would contain:
    /usr/lib/aarch64-linux-gnu/mali
  That single line is what a real install uses to put Mali ahead of Mesa
  system-wide. It is deliberately NOT installed; the private runtime
  directory plus LD_LIBRARY_PATH does the same job for one process.

The three generic sonames are 5928-byte shims that define no symbols of
their own. They exist only to satisfy DT_NEEDED for binaries linked
against Mesa sonames; every EGL/GLES/GBM entry point resolves through
libmali.so.1, with libmali-hook.so.1 interposing a few of them
(eglGetPlatformDisplay, eglGetDisplay, eglChooseConfig, gbm_bo_create,
gbm_surface_create, gbm_bo_import, gbm_bo_get_modifier, ...).
Consequence: Kodi needs no rebuild to use this stack, because its
DT_NEEDED entries are already the generic sonames.
