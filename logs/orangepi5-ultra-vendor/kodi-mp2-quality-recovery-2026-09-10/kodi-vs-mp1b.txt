Kodi DRMPRIME vs the proven MP1b raw playback probe
===================================================

Purpose: settle whether the washed-out HDR appearance the operator reported
is something Kodi does, or something this display does.

Corrected reading (after Windows and physical follow-up A/B tests)
  The reference path and Kodi are indistinguishable, measured and seen. Kodi
  is therefore not a regression against the MP1b probe, but that probe is not
  an independent proof of correctness: both RK3588 paths pass through the same
  4000-nit source mastering maximum.

  Windows + Kodi renders the same file correctly on this same BenQ RD280UG,
  disproving the original sink-limitation inference. However, changing the
  RK3588 mastering maximum from 4000 to the panel's decoded 418 nits made no
  visual difference. Explicit Limited/Full quantisation and RGB 10-bit output
  also made no improvement; RGB additionally removed GUI text. All temporary
  changes were reverted.

  FINAL CORRECTION: EOTF is present but atomic-only; legacy `modetest -p` hid
  it. With `modetest -a -p`, plane 73 exposes property 31 and initially reads
  EOTF=0. Kodi patch 0008 now sets EOTF=2 for PQ NV15 video. Readback and VOP
  summary both report HDR10[2], and the operator reports a clear improvement
  in film colours on a second HP X27q monitor. NV15 and 10-bit YCbCr remain.

  The remaining washed player-control blue is isolated to the GUI plane:
  Kodi's GUI compositor writes PQ pixels, but plane 57 remains EOTF=0, causing
  a second SDR-to-HDR conversion. Patch 0009 is the proposed userspace fix.
